# Goals — Advanced Kanban Todo (Long-term + Regular) Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Add a `/goals` route — an advanced, semi-Kanban todo board for future goals with two horizons (LONG-TERM / REGULAR), drag-and-drop status columns, milestone checklists, due dates, and full integration (nav, dashboard, backup export/import).

**Architecture:** New Dexie v3 tables `goals` + `milestones` (local-only, per user mandate — NO remote DB). Client-side actions in `src/app/actions.ts` following the existing same-name-export pattern. One `"use client"` page rendering a 3-column board (BACKLOG → IN PROGRESS → DONE). Desktop: native HTML5 drag-and-drop (zero new deps). Mobile/touch: explicit MOVE buttons on each card (HTML5 DnD is mouse-only — this is mandatory, not optional). Horizon is a card attribute + segmented filter, not separate boards.

**Tech Stack:** Next.js 16 App Router, React 19, Dexie (v3 migration), Tailwind v4 tokens, framer-motion (existing), lucide-react icons, existing `ui.tsx` primitives (Button/Card/Badge/Input/Textarea/Modal/EmptyState).

**Conventions to obey (from study-app skill):**
- Every page hero = `RevealHeading` + `ScrambleSubtitle` (import `@/components/scramble-subtitle`).
- `Modal` already portals to body — use it as-is.
- Inputs have NO label wiring — E2E must target by placeholder.
- **Design system is "Aurora Glass" (DESIGN.md v2) — NOT the old ONYX brutalist look.** Glass surfaces (`glass` class / ui.tsx `Card`), rounded-full pill buttons, generous radius (12–24px), semantic tokens only: `accent` (hot signal), `flow` (progress — milestone bars, IN PROGRESS, drop hints), `grow` (success/done), `danger` (overdue). NO hardcoded `zinc-*`/`yellow-*`/`red-*` classes anywhere — everything must adapt to all 12 themes.
- Uppercase is reserved for eyebrows/badges only (the `Badge` component already does `uppercase tracking-widest`); titles/body stay normal case. Headings use Space Grotesk via `font-display` (`RevealHeading` handles it).
- E2E text assertions: badges/eyebrows render CSS-uppercased — assert UPPERCASED form there; titles render as typed.
- Digits get `font-mono tabular-nums` (big stat numerals use `font-display` Space Grotesk instead, per DESIGN.md §3).
- Motion thesis: soft-spring, physical — cards float in with stagger (framer-motion variants as MODULE CONSTANTS), hover lift `-translate-y-1`.
- Transition/font objects for animations must be module constants (re-render replay pitfall).
- Never `setState` synchronously inside a `useEffect` body (React 19 lint error).
- Gates: `npm run build` AND `npm run lint` must both pass.

**Step 1: Add the full goals section** (complete, copy-pasteable):

```ts
// ═══════════════════════ GOALS (kanban todo) ═══════════════════════

export async function getGoals(): Promise<GoalRec[]> {
  return db.goals.orderBy("createdAt").toArray();
}

export async function createGoal(data: {
  title: string;
  description?: string;
  horizon: GoalHorizon;
  dueDate?: Date | null;
  subjectId?: string | null;
  color?: string | null;
}): Promise<GoalRec> {
  const inBacklog = await db.goals.where("status").equals("backlog").count();
  const now = new Date();
  const goal: GoalRec = {
    id: uid(),
    title: data.title.trim(),
    description: data.description?.trim() || null,
    horizon: data.horizon,
    status: "backlog",
    order: inBacklog,
    dueDate: data.dueDate ?? null,
    subjectId: data.subjectId ?? null,
    color: data.color ?? null,
    createdAt: now,
    updatedAt: now,
    completedAt: null,
  };
  await db.goals.add(goal);
  return goal;
}

export async function updateGoal(
  id: string,
  data: Partial<{
    title: string;
    description: string | null;
    horizon: GoalHorizon;
    dueDate: Date | null;
    subjectId: string | null;
    color: string | null;
  }>
): Promise<void> {
  await db.goals.update(id, { ...data, updatedAt: new Date() });
}

export async function moveGoal(id: string, status: GoalStatus, index: number): Promise<void> {
  // Pull the goal, reindex the target column, insert at `index`.
  const goal = await db.goals.get(id);
  if (!goal) return;
  const col = await db.goals.where("status").equals(status).sortBy("order");
  const rest = col.filter((g) => g.id !== id);
  const clamped = Math.max(0, Math.min(index, rest.length));
  await db.transaction("rw", db.goals, async () => {
    for (let i = 0; i < rest.length; i++) {
      const newOrder = i >= clamped ? i + 1 : i;
      if (rest[i].order !== newOrder || rest[i].id === id) {
        await db.goals.update(rest[i].id, { order: newOrder });
      }
    }
    await db.goals.update(id, {
      status,
      order: clamped,
      updatedAt: new Date(),
      completedAt: status === "done" ? new Date() : null,
    });
  });
}

export async function deleteGoal(id: string): Promise<void> {
  // Genuine cascade — milestones must die with the goal (gotcha #8).
  await db.milestones.where("goalId").equals(id).delete();
  await db.goals.delete(id);
}

export async function getMilestones(goalId: string): Promise<MilestoneRec[]> {
  return db.milestones.where("goalId").equals(goalId).sortBy("order");
}

export async function createMilestone(goalId: string, title: string): Promise<MilestoneRec> {
  const count = await db.milestones.where("goalId").equals(goalId).count();
  const ms: MilestoneRec = {
    id: uid(),
    goalId,
    title: title.trim(),
    done: false,
    order: count,
    createdAt: new Date(),
  };
  await db.milestones.add(ms);
  await db.goals.update(goalId, { updatedAt: new Date() });
  return ms;
}

export async function toggleMilestone(id: string, done: boolean): Promise<void> {
  await db.milestones.update(id, { done });
}

export async function deleteMilestone(id: string): Promise<void> {
  await db.milestones.delete(id);
}
```

## Risks / tradeoffs / open questions

- **HTML5 DnD is desktop-only** — accepted; touch users get explicit move buttons (that's the "semi" in semi-kanban). If the user later wants touch-drag, swap in `@dnd-kit` (one dependency) without touching the data layer.
- **Order reindexing** is O(column) per move — fine at todo scale.
- **No notifications/reminders for due dates** (YAGNI) — overdue is surfaced visually on the card + stats row.
- **Horizon naming** — UI copy is EN ("LONG-TERM" / "REGULAR") to match the app's all-caps EN interface; the semantics map to بعيد المدى / عادي.
- Bottom nav grows to 7 items — verified in Task 8 Step 4; fallback is icon-only at ≤360px.
